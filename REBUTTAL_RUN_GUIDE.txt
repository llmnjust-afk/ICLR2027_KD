一 这次实现覆盖什么

主实验采用 ImageNet-100、IPC=10、冻结 DiT-XL/2、50 步去噪、CFG=4.0。
自适应对象是额外模态引导系数，不是 CFG。原始结果目录不会被覆盖。

新增入口：python -m rebuttal.run
多卡入口：bash scripts/rebuttal.sh
配置模板：rebuttal.example.env
核验测试：tests/test_rebuttal.py、test_resources.py、test_transfers.py、test_launcher.py

默认 full 正式实验包括：
  no_mode：关闭额外模态引导，保留 CFG=4。
  cags：两因素类别自适应。
  fixed_mean：固定为同一批实际 CAGS 系数的均值。
  fixed_best_<architecture>：在独立调参集上选出的固定强度。
  cags_selected_<architecture>：在独立子集上重新选择权重、Sigmoid 和范围后的配置。
  selected_fixed_mean / selected_permuted：独立选出配置自己的平均系数和三次置换对照。
    如果选出的系数向量与预设 CAGS 完全一致，会复用 cags 及其对照，不重复计算。
  permuted_17 / 29 / 43：三组固定的类别系数随机置换。
  entropy / dispersion / four_factor：三种因素配置。
  entropy_mean_matched / dispersion_mean_matched / four_factor_mean_matched：
    通过移动 logit 截距，将各因素配置平均系数匹配到 CAGS，保持系数范围与排序。
  inherited_mgd_fixed_0p10_window25：继承的 MGD3 模态更新、固定 0.1、25 步窗口。
  inherited_mgd_fixed_0p10_stop0：继承采样脚本的 guidance=True、系数 0.1、stop_t=0 设置。

后两项用于在当前统一流程内检查继承的 MGD3 固定模态引导。
它们没有被标成“已独立核实的公开论文最优配置复现”。公开 MGD3 的完整协议仍需核对。

四 单机多卡最直接的运行方式

  bash scripts/rebuttal.sh prepare
  bash scripts/rebuttal.sh tune
  bash scripts/rebuttal.sh final

可使用 nohup，三个阶段顺序执行：
  nohup bash -c 'set -e; bash scripts/rebuttal.sh prepare; bash scripts/rebuttal.sh tune; bash scripts/rebuttal.sh final' > rebuttal_pipeline.log 2>&1 &

查看进度：
  tail -f rebuttal_pipeline.log
  bash scripts/rebuttal.sh status tune
  bash scripts/rebuttal.sh status final

工作线程的详细日志位于：
  WORKDIR/runs/tune/worker_logs/
  WORKDIR/runs/final/worker_logs/

prepare 只需要运行一次。它会：
  1. 对每类真实训练图像按固定种子留出 10% 作为独立调参集。
  2. 剩余 90% 才用于特征提取、复杂度分析和生成模态目标。
  3. 使用 VAE latent mean，不对特征随机采样；默认中心裁剪、不随机翻转。
  4. 保存每张参与特征提取的原图 SHA-256、特征文件哈希及模态目标哈希。
  5. 创建 auto-K 和固定 K=2/5/10 的复杂度配置；所有配置共享生成目标。

缓存固定后不可静默覆盖。要改变训练划分、IPC、特征或预处理，请换 WORKDIR。
新实验的特征提取和最终 epoch 协议已经显式固定，与历史表格可能不同；
所有新方法和基线都按同一协议重评，不能将新结果直接拼进旧表却省略协议变化。
独立重新调参不能追溯改变历史实验使用过验证集的事实；回复中仍应如实说明旧流程，
再将本次独立划分、冻结参数后的新实验作为补充证据。

五 两台或多台机器并行

前提：代码、ICLR 环境、模型、数据及 WORKDIR 位于所有机器都可访问的共享路径。
每张卡启动一个工作进程；共享文件队列通过原子锁避免重复领取任务。

只在一台机器上准备缓存和创建调参计划：
  bash scripts/rebuttal.sh prepare
  bash scripts/rebuttal.sh plan-tune

随后在每台机器分别执行，例如：
  REBUTTAL_GPUS=0,1,2,3,4,5,6,7 bash scripts/rebuttal.sh workers tune

REBUTTAL_GPUS 可以覆盖配置文件里的 GPUS，适合各机器可用编号不同的情况。
可以 nohup 启动 workers；各机器日志文件带主机名，不会互相覆盖。

所有调参任务完成后，在任意一台机器执行一次：
  bash scripts/rebuttal.sh select
  bash scripts/rebuttal.sh plan-final

然后在每台机器执行：
  REBUTTAL_GPUS=0,1,2,3,4,5,6,7 bash scripts/rebuttal.sh workers final

全部完成后汇总：
  bash scripts/rebuttal.sh summary final

4090 和 A800 可以共同领取任务。同一个生成种子下的各方法会绑定到相同 GPU 型号，
但允许分布到同型号的不同卡；同一个生成种子、训练种子、架构的分类比较由一个工作进程完成。
这样既能并行生成，也避免在一个配对比较内部混用 4090 与 A800。
硬件型号和库版本均被记录；统计结果仍应披露使用了哪些硬件。

若不同机器不共享文件系统，应使用各自独立 WORKDIR 并保留原始记录；
不要直接把一台机器的共享队列文件复制给另一台机器同时执行。
当前这套自动合并流程针对共享文件系统，不包含跨独立文件系统的结果合并器。

六 默认任务量与优先安排

默认仅运行 ConvNet-6：
  调参：生成种子 0/1/2，训练种子 0；
    13 个 CAGS 候选与 13 个可选择的共享系数候选，另保留固定 0.10 作为参考，共 27 组；
    81 份生成数据集、81 次分类器训练，2000 epochs。
    CAGS 候选包括默认、仅熵、仅离散度、四因素、两种熵/离散度权重比例、
    slope=2/5、center=0.4/0.5/0.7、maximum=0.04/0.08 的单因素变体。
    固定系数候选为 0/0.005/0.01/0.015/0.02/0.025/0.03/0.035/0.04/0.045/0.05/0.06/0.08。
    两个候选族使用相同独立调参数据、训练轮数、生成种子及 13 个可选择候选的预算。
    0.10 保留作历史固定强度参考，不参与 [0,0.08] 内最佳固定值选择。
    固定值 0 也可获选，避免预设“必须存在有益的非零引导”。
    CAGS 以调参均值最高者获选；相同分数先选非零因素较少者，再按候选名称排序。
    如果仅熵、仅离散度或四因素获选，应如实报告，不能人为强制两因素获胜。
  正式 full：生成种子 100/101/102/103/104，训练种子 0/1/2；
    单架构 15 至 20 组，75 至 100 份生成数据集、225 至 300 次分类器训练，2000 epochs；
    数量取决于独立选出的配置是否与原预设一致。

实际计划会打印任务数量，不能把多架构配置仍按上述单架构数量估算。

如果希望先拿到核心因果对照，将配置里的 FINAL_SUITE 改为 core：
  核心对照加两项继承固定引导及必要的独立选出配置对照，共 9 至 14 组，
  45 至 70 份生成数据集、135 至 210 次分类器训练。
  正式计划一旦创建，不要在同名 final 下切换 suite。
  完成 core 后，可独立执行因素实验：
    bash scripts/rebuttal.sh plan-factors
    bash scripts/rebuttal.sh workers factors
    bash scripts/rebuttal.sh summary factors
  独立实验计划会重新生成自己的数据，避免把不同计划的记录静默混为同一批实验。

4090 默认生成 batch=4、分类器 batch=128；A800 使用相同 batch，保证协议匹配。
如果实际显存不足，应在创建调参计划前修改 GEN_BATCH_SIZE/TRAIN_BATCH_SIZE，
并在最终计划中保持一致。已冻结计划不会静默接受不同 batch。

需要跨架构时，在调参和正式计划创建前设置：
  ARCHITECTURES=convnet6,resnet18,resnetap10
每个架构分别在独立调参集上选择最佳固定系数。
程序会拒绝对从未调参的架构宣称“该架构的最佳固定强度”。

EPOCHS=500、较少种子可以用于独立 WORKDIR 下的预检查，
但不能把这类结果与 2000 epoch 正式结果混合，也不能把 proxy 的最佳系数自动转为全协议最优。
程序要求正式实验与其调参实验在 epoch、优化器、采样、batch 和精度等关键参数上匹配。

七 统计输出如何对应审稿意见

输出位于：
  WORKDIR/runs/final/summary.json
  WORKDIR/runs/final/raw_results.csv
  WORKDIR/runs/final/evaluation/g<生成种子>/t<训练种子>/<架构>/<方法>.json

summary.json 报告：
  每个生成种子内先平均训练种子的准确率；
  独立生成重复间的样本标准差；
  CAGS 与各对照的逐生成种子配对差值；
  配对差值均值、95% t 区间、双侧 p 值、明确定义的 Cohen dz；
  同一架构比较族内的 Holm 校正 p 值；
  CAGS 相对三次置换平均结果的配对差值。

3 个训练种子不是 3 次独立生成。默认正式比较的 n_generation=5，而不是 15。
这些区间以固定的真实数据划分、特征缓存和模型权重为条件，
没有额外估计不同特征提取种子、不同训练子集划分造成的方差。

未完成全部配对任务时，正式 summarize 会拒绝推断统计。
只看进度可执行：
  python -m rebuttal.run summarize --plan "$WORKDIR/runs/final" --allow-partial
该模式不输出不完整配对结果的显著性结论。

重点解读：
  cags_minus_fixed_mean：类别分配与平均强度的区分。
  cags_minus_fixed_best_<architecture>：相对独立调优共享系数的差异。
  cags_minus_permuted_average：系数分配到正确类别是否有效。
  cags_selected_<architecture>_minus_*：独立重新调参后的相应比较。
  cags_minus_entropy / dispersion / four_factor：因素配置比较。
  *_mean_matched：平均强度被控制后的因素配置比较。
  inherited_mgd_*：当前继承采样更新在同一评估流程下的固定引导结果。

八 特征和聚类敏感性

prepare 默认已保存相同 VAE 特征下 auto-K 与 K=2/5/10 的复杂度配置。
正式主实验之后执行：
  bash scripts/rebuttal.sh plan-sensitivity
  bash scripts/rebuttal.sh workers sensitivity
  bash scripts/rebuttal.sh summary sensitivity

这些配置只改变复杂度估计器，生成模态目标仍固定。
PCA 的随机初始化按类别固定，不因前一个类别或 K 配置消耗了不同随机数而改变。
同时生成原系数和平均强度匹配后的版本，便于区分估计器与整体强度的作用。

若还要比较特征提取器，在第一次 prepare 前填写：
  RESNET_FEATURE_CKPT=/path/to/torchvision_resnet18_imagenet_state_dict.pth
这应是 torchvision ResNet-18 的完整 ImageNet state_dict，不是本项目蒸馏分类器的检查点。
程序会额外提取 ResNet-18 特征并建立 resnet18_auto 配置；模态目标仍来自相同 VAE 缓存。

也可以手动准备 PCA 维度变体，例如：
  python -m rebuttal.run prepare --workdir /new/workdir --data-root /path/to/imagenet100 \
      --vae /path/to/sd-vae-ft-mse --pca-variants 2,8 --local-files-only

九 自适应 CFG 对照的准确定位

可运行内部时变 CFG 消融：
  bash scripts/rebuttal.sh plan-cfg-controls
  bash scripts/rebuttal.sh workers cfg_controls
  bash scripts/rebuttal.sh summary cfg_controls

其中包括高噪声阶段 CFG=4、低噪声阶段 CFG=1 的窗口方案，
以及 CFG 从高噪声 4 线性降低到低噪声 1 的退火方案；分别与固定均值模态引导、CAGS 组合。
这里 CFG=1 表示标准条件预测，并不是无条件预测。

这些是明确记录的内部消融，没有冒称 PACFG、ECAI adaptive scaling 等已发表方法的忠实复现。
本次外部文献与官方实现访问失败，代表性已发表自适应方法的移植仍需在取得规范后完成。
因此，这一组结果能讨论 CFG 时间维度与模态引导类别维度的关系，
不能写成“已经优于已有自适应 CFG 方法”。

十 断点续跑和失败处理

正常中断后，再次执行相同 workers 命令，已完成的生成数据集和分类器结果会验证后跳过。
同一批结果不允许混入不同代码、库版本、权重、数据划分或协议。

失败记录位于：
  WORKDIR/runs/<name>/queue/*.failed.json
其中包含完整 traceback 和硬件信息。

先检查原因并停止有问题的进程，再将失败任务重新入队：
  bash scripts/rebuttal.sh retry-failed final
  bash scripts/rebuttal.sh workers final

如果需要改 Python 代码或关键协议，应先备份并创建新计划，
不能修改源代码后继续把新结果记到旧计划。旧计划中的同版本成功结果仍保留。

kill -9 或机器掉线可能留下 .lock。status 会显示锁的主机、PID、时间。
只有确认对应工作进程已经退出后，才能把该锁移到备份位置再续跑；
脚本不会仅凭超时抢占仍可能在运行的任务。

生成配对块和部分完成的分类配对块续跑时，需使用相同 GPU 型号。
跨型号恢复会拒绝执行，避免把硬件变化混进同一配对比较。
